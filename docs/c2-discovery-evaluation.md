# 探索推荐与离线验证

2026-10-30。聊天、`GET /api/recommend`、推荐工具和 CLI 默认使用探索推荐。收到同一问题时，不按借阅量排列书单：有本人历史时，结合内容相似度、相似读者和分类偏好；没有历史时从候选书目均匀抽样，不声称了解读者兴趣。读者明确要求“热门”等内容时，先在符合主题的书中选出历史借阅较多的候选，再抽样换批；这不是实时热度。显式热门榜 `/api/hot-books` 仍报告实际历史借阅排行。

## 主题和换批

- 支持常见自然语言中的书名、作者、题名词和部分明确的中图分类词（例如计算机、文学）；`query` 可单独传主题。匹配基于已有字段，不是深层语义检索；无法直接匹配时返回空列表，不以其他主题凑数。
- 明确要求热门时，候选充足的情况下选取不少于两批、至少 10 本历史借阅较多的书，并保留边界上的并列项；若无借阅记录，不伪造热门。题名用《》括住时，书名内的“热门”不触发筛选。
- 已认证读者的历史借阅先过滤，精确归并的同书也不会补回。兴趣分依据内容、协同、分类分别按 0.65、0.25、0.10 组合，内容和协同相对当前候选归一化；在相关候选池内加权抽样，分数不等于命中概率。
- 同一进程中，同一会话和主题优先避开上一批；多个同时到达的请求也有轮换保护。匿名会话由随机访问 cookie 区分，已认证会话按身份区分。候选不足时会重复；服务重启、多 worker 或会话变化后不保证延续上一批。只在内存中保存有界的上一批图书标识，不保存借阅流水。
- 若指定主题没有匹配书目，聊天会明确提示；可换用书名、作者或类别。推荐不代表实时可借，也不能从索书号推断实际架位。

```powershell
# 直接使用已提交的虚构书目
python -S -m data.scripts.recommend --data-dir data/fixtures/integration --query Python
# 真实数据已在本地按共享清单准备后，仅输出无个人明细的评估汇总
python -S -m data.scripts.evaluate_discovery --data-dir data/processed/shared-real
```

`Recommender.discover()` 支持可选主题、分类和 `avoid` 书目；直接调用时由调用方提供上一批标识。原有 `Recommender.recommend()`、`hybrid` 等确定性策略保留用于可复现基线，CLI 可通过 `--strategy hybrid` 等显式调用。聊天和 HTTP 会处理各自的会话轮换。

## 真实样本离线对照

本地使用 36,908 条借阅样本，排除旧评估的 200 名读者，再排除先前报告使用过的 600 名验证读者和 600 名测试读者，从剩余读者中选取 100 人测试。训练前移除先前 1,200 人及本次 100 人留出目标的全部复借流水，共 1,408 条，保留静态书目。使用固定随机种子，比较每人的前 5 本与留出的一本：

| 100 名测试读者的留出命中 | 命中人数 |
| --- | ---: |
| 旧 hybrid 基线 | 9 |
| 探索推荐第一批 | 10 |
| 避开第一批后的第二批 | 3 |

这 100 人的两批推荐均无重复图书，且未包含训练中已读图书。两批命中数不同，第二批的相关性仍有提升空间。样本没有借阅日期，且测试人数有限；上述数字不能当作未来借阅、满意度或线上效果。真实资料及逐人结果不进入仓库。
