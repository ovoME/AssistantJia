# 「小嘉」生产部署手册（D：全栈/集成协调）

> 仓库：`ovoME/AssistantJia`（私有）｜ 接口契约：`docs/api-contract.md`
> 环境变量：`.env.example`（`LLM_API_KEY` / `LLM_BASE_URL` / `LLM_MODEL` / `EMBEDDING_MODEL_NAME`）

## 一、服务器要求

| 项目 | 最低要求 | 建议 |
| --- | --- | --- |
| 操作系统 | Ubuntu 22.04 LTS 或 Debian 12 | 同左（云主机） |
| CPU / 内存 | 4 核 8 GB | 8 核 16 GB（嵌入模型本地部署时） |
| 磁盘 | 40 GB 空闲 | SSD，100 GB+（向量库+日志+镜像） |
| Docker | Docker Engine 24+ | 含 Compose v2 插件 |
| 网络 | 可访问大模型 API | 出口放通 HTTPS(443) 到模型服务商 |

> ⚠️ 步骤1 人工确认项（D 负责）：确认服务器可登录、SSH 权限、Docker 已安装可用。未确认前不得进入部署。

## 二、首次部署

### 1. 服务器环境准备

```bash
curl -fsSL https://get.docker.com | sh
sudo systemctl enable --now docker
docker --version && docker compose version

# 建议为部署创建专用用户，避免 root 直接操作
sudo adduser xiaojia
sudo usermod -aG docker xiaojia
```

### 2. 拉取代码与环境配置

```bash
mkdir -p /opt/xiaojia && cd /opt/xiaojia
git clone https://github.com/ovoME/AssistantJia.git .
cp .env.example .env
# 编辑 .env：填 LLM_API_KEY、LLM_BASE_URL、LLM_MODEL 等
```

### 3. 构建并启动

```bash
docker compose up -d --build
docker compose ps              # 四个服务全部 healthy 即成功
curl http://localhost:8000/health        # {"code":0,...,"data":{"status":"healthy"}}
# 浏览器打开 http://localhost  → 读者端/管理端
# Swagger 文档：http://localhost:8000/docs
```

服务端口：前端 `80`｜后端 `8000`｜Redis `6379`｜Chroma `8001`（外部映射）。

## 三、HTTPS 与域名

生产环境必须启用 HTTPS，二选一：

- **方案 A（推荐，自动续期）**：Caddy 反向代理 `127.0.0.1:80`，自动申请 Let's Encrypt 证书。
- **方案 B（Nginx + certbot）**：Nginx 反代 `127.0.0.1:80`，certbot 配置自动续期。

> 校内域名需网络中心/馆方配合备案；无域名时 IP + 自签证书仅供演示。

## 四、数据初始化（首次/升级后）

按 C 的产物执行（`data/pipeline.py` 已合入 develop，脚本见 `data/scripts/`）：

```bash
# 示例：清洗并入库借阅数据（36,908 条）
docker compose exec backend python /app/data/scripts/clean_data.py

# 知识库向量化（Chroma）
docker compose exec backend python /app/data/scripts/build_kb.py  # 以 C 提供脚本为准
```

## 五、日常运维

| 操作 | 命令 |
| --- | --- |
| 查看日志 | `docker compose logs -f backend` |
| 重启单个服务 | `docker compose restart backend` |
| 升级（CI 自动部署后） | 无需手动，deploy.yml 已 SSH 执行 `pull + up -d` |
| 回滚 | 服务器上 `docker compose up -d --no-deps backend`（用旧镜像 tag） |
| 备份 | Chroma 卷 `docker compose exec chroma tar -czf /data/backup.tgz /chroma/chroma`；Redis `redis-cli SAVE` |
| 清理 | `docker image prune -f` |

## 六、安全基线

- 防火墙仅放行 80/443 与 SSH；8000/6379/8001 不对公网开放。
- SSH 禁止密码登录，使用密钥。
- `.env` 权限 `chmod 600`；`LLM_API_KEY` 等严禁入库、严禁贴给 AI。
- 管理端 `/api/admin/*` 按团队确认的鉴权方案（建议 `X-Admin-Token` 头，对应新增环境变量）。
- 读者数据（证件号等）在日志与响应中脱敏。

## 七、故障排查（D 的定位工作流）

> 原则：出问题先把日志贴给 AI，让它给出排查步骤与修复方案；自己试 2 次 + 问 AI 2 次仍无解，立即群里同步（阻塞升级）。

| 症状 | 排查步骤 |
| --- | --- |
| 页面 502 | 1) `docker compose ps` 看 backend 是否 healthy；2) `docker compose logs backend`；3) 检查 .env 是否缺 LLM_API_KEY |
| 对话无回复/转圈 | 1) backend 日志是否有模型 API 报错；2) `curl http://localhost:8000/health`；3) 检查 LLM_API_KEY 有效性与余额 |
| 查书无结果 | 1) 确认 OPAC 接口/爬虫可用（C）；2) backend 日志中 search_books 工具报错；3) 网络可达馆方系统 |
| RAG 答非所问 | 1) 检查 Chroma 向量是否导入；2) 优化切分策略（C 负责） |
| 磁盘爆满 | `docker system df` → `docker image prune -a` |
| CI 绿、本地启动失败 | 1) Docker ≥24 + Compose v2；2) `.env` 是否复制；3) `docker compose pull` |
