# C2 内容融合优化与独立测试

2026 年 10 月 24 日，使用同一份 36,908 条真实借阅流水、3,580 位读者和归并后的 22,587 本书目。原 hybrid 方案加入题名、责任者及细分分类的内容相似度，使零训练借阅次数的书也能被召回。下列结果只适用于该确定性基线；当前交互探索推荐的效果与限制见 [探索推荐评估](c2-discovery-evaluation.md)。

## 如何避免在测试集上调参

1. 从借过至少两个不同书种的读者中，排除上一版已查看的 200 人样本；排除规则与原验证工具完全相同。
2. 用固定 SHA-256 哈希排序，在剩余读者中分出互斥的 600 人验证集和 600 人测试集。每人按另一固定哈希选一个归并书种留出。种子和规则固定在 `data/scripts/compare_recommendations.py` 的 `SPLIT_VERSION` 与 `split_readers()` 中。
3. 训练前同时移除两个集合目标书的全部复借事件及其别名，共 1,299 条，剩余 35,609 条训练流水。重算热门度、偏好和邻居；保留静态书目元数据，包含零训练借阅次数的书。两种算法使用完全相同的训练集、候选目录和目标。
4. 仅在验证集比较预先列出的五个内容权重；按 Hit Rate@10、再 MRR@10、再较小权重选择。冻结为 0.75 后，才运行测试集的旧方案与选定方案。没有按测试结果再修改特征、权重或过滤规则。

文档中的“独立”指评估读者集合互斥且测试目标不参与选参数；这些读者的其余历史仍用于个性化训练，并不是全新读者的冷启动实验。静态内容索引使用完整书目元数据，不使用被留出的借阅事件；这假设书目在推荐时已知，不代表对未来新增书目的预测。

## 验证集选型

| 内容权重 | 命中人数/600 | Hit Rate@10 | MRR@10 |
| --- | ---: | ---: | ---: |
| 0（首版基线） | 27 | 4.50% | 0.022665 |
| 0.25 | 86 | 14.33% | 0.063894 |
| 0.50 | 106 | 17.67% | 0.078104 |
| 0.75（选定） | 108 | 18.00% | 0.079440 |
| 1.00 | 104 | 17.33% | 0.073917 |

0.75 与 0.50 的差距只有 2 人；该结果支持采用内容特征，但不说明 0.75 是普遍最优权重。

## 冻结后的测试集结果

| 指标 | 首版混合基线 | 内容融合混合 |
| --- | ---: | ---: |
| 测试读者 | 600 | 600 |
| 前 10 本命中人数 | 22 | 115 |
| Hit Rate@10 | 3.67% | 19.17% |
| MRR@10 | 0.022838 | 0.090950 |
| NDCG@10 | 0.026026 | 0.114409 |
| 目标仍有训练借阅：命中/人数 | 22/286 | 58/286 |
| 目标无训练借阅：命中/人数 | 0/314 | 57/314 |

同一批 600 人中，98 人仅新方案命中，5 人仅旧方案命中，17 人两者均命中。总体提高 15.50 个百分点；没有排除零训练次数的 314 个目标，也没有只报告容易命中的书。每人一个相关目标，因而这里的 Hit Rate@10 也等于该留一设置的 Recall@10，不是推荐列表中相关图书的比例。

旧方案定义为提交 `08e76b2` 的混合规则。评估中内容权重设为 0 时不做额外归一化，保留原公式；另以该提交的原始 Python 实现对 50 位真实读者、空读者和未知读者的四种策略做 208 次差分查询，结果逐字段完全一致。

上述 3.67% 与先前 200 人报告的 3.0% 来自不同拆分；本次提升比较的是同一测试集的 3.67% → 19.17%，不能把旧 200 人和新 600 人直接比较。当前没有日期，这仍是离线历史留出，不能据此承诺线上命中率或读者满意度。测试集结果现已公开，后续调参应使用新的预留样本或新增数据，不再把这批数据当未见测试集。

## 复现

先按 [真实数据验证](c2-real-validation.md) 生成本地清洗目录，再运行：

```powershell
python -S -W error -m data.scripts.compare_recommendations --data-dir data/processed/c2-real-validation/cleaned --phase validation --output data/processed/c2-real-validation/content-validation.json
python -S -W error -m data.scripts.compare_recommendations --data-dir data/processed/c2-real-validation/cleaned --phase test --selection data/processed/c2-real-validation/content-validation.json --output data/processed/c2-real-validation/content-test.json
python -S -W error -m data.scripts.validate_recommendations --data-dir data/processed/c2-real-validation/cleaned --limit 20 --holdout-readers 0 --output data/processed/c2-real-validation/optimized-functional.json
```

测试阶段要求验证报告的源文件 SHA-256、拆分人数、版本和当前默认权重一致；改变输入后，验证集可能选出不同权重，此时命令会明确拒绝直接测试。`--legacy-size` 默认 200，不应为改善真实指标改为 0；CI 仅用互不相关的虚构数据设置为 0 做小样本流程检查。

报告只写汇总、输入文件摘要和参数；真实源表、证件号、逐人书单、清洗记录、内容索引保留在本地忽略目录，没有提交到仓库。

## 回归与接入

Python 3.12.14 下，pandas 2.2.3 和 3.1.0 各 47 项回归测试通过，警告按错误处理。CI 新增标准库对照 CLI 的虚构数据验证阶段；单元测试另外检查测试阶段必须使用同一拆分并冻结权重。

优化后再次对全部 3,580 位读者运行四种策略、limit=20，共 14,320 次查询、286,400 条推荐，已读重叠、同单重复、空结果均为 0；分数范围、书目归属、字段、来源标签和四种策略冷启动检查通过。此轮功能检查设置 holdout_readers=0，效果指标只引用上文独立对照结果。

新增内容计算有额外成本。本轮混合推荐查询中位耗时约 22.7 毫秒、P95 约 36.1 毫秒；这是本机复用已加载实例的观察值，未做受控并发压测，也不代表 HTTP 延迟或线上吞吐。

现有 HTTP 推荐路由仍使用 mock；本次交付为 C2 推荐算法优化，不代表线上接口已经切换。
